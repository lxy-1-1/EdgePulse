# 项目讲解与继续开发

## 需要能亲自解释的五件事

1. **超时为什么不能直接删队列？** 服务端可能已经提交，只是响应丢失；持久化队列和幂等键一起解决重试与重复处理问题。
2. **为什么批次整体回滚？** 部分样本和告警已更新、后半批才发现冲突，会让客户端难以决定重试范围。
3. **为什么有 boot_id？** 重启后序号可能归零，用启动周期区分新数据和旧重传。
4. **防抖、迟滞和 ACK 各有什么用？** 分别过滤尖峰、防止阈值边界抖动、记录人工操作；确认不能修改设备事实。
5. **取消异步任务为何不一定停止写入？** `asyncio.to_thread` 的线程不会随等待协程取消而结束；本项目使用协作式停止并等待当前写入。

## 阅读与练习

`tests/test_store.py` → `store.py` → `agent.py` → `tests/test_simulator.py` → `app.py` → `scripts/test_ui_state.cjs`。

先运行测试，手动改变一个关键条件（例如去掉冲突回滚），观察测试失败，再恢复代码。理解哪个断言保护了哪个行为。

## 后续扩展

- 接实物，记录型号、校准、误差和真实断网/重启实验。
- 每设备独立凭据，保证设备只能上报自己的数据。
- 数据保留与分区，测量长时间运行的查询和清理成本。
- 增加 MQTT 入口，保持相同幂等契约。
- 用真实数据比较阈值和统计检测，报告误报、漏报与延迟。

简历里描述已经验证的设计和结果。不要把模拟数据说成真实工厂部署，或把本地入库速度说成网络吞吐。能够现场解释、修改和复现，才是项目的实际价值。
